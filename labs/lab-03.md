## 📚 Теоретичні відомості

### WebSocket протокол

**WebSocket** є комунікаційним протоколом, який забезпечує повнодуплексний (двосторонній) канал зв'язку через одне TCP-з'єднання. На відміну від HTTP, де клієнт завжди ініціює запит, WebSocket дозволяє серверу надсилати дані клієнту в будь-який момент без попереднього запиту. Протокол описано в RFC 6455.

**Основні переваги WebSocket:**

- Низька латентність комунікації між клієнтом та сервером;
- Менше навантаження на мережу порівняно з періодичним опитуванням (polling);
- Підтримка двостороннього обміну даними в реальному часі;
- Ефективне використання ресурсів сервера.

**Процес встановлення WebSocket з'єднання:**

1. Клієнт надсилає HTTP-запит із заголовком `Upgrade: websocket`;
2. Сервер підтверджує upgrade та повертає статус 101 Switching Protocols;
3. З'єднання переходить від HTTP до WebSocket протоколу;
4. Встановлюється постійне з'єднання для двостороннього обміну повідомленнями.

### Socket.io бібліотека

**Socket.io** є JavaScript-бібліотекою для двосторонньої комунікації в реальному часі між браузерами та серверами. Вона надбудовується над протоколом WebSocket і додає власний протокол обміну повідомленнями. Тому клієнт Socket.io не може підключитися до «чистого» WebSocket-сервера, і навпаки: на клієнті потрібна бібліотека `socket.io-client`, а не вбудований `WebSocket` браузера. У курсі використовується Socket.io 4.

**Ключові особливості Socket.io:**

- Автоматичний перехід на HTTP long-polling, якщо WebSocket недоступний;
- Автоматичне повторне підключення (reconnection) при втраті з'єднання;
- Розсилка повідомлень багатьом клієнтам одночасно (broadcast);
- Кімнати (rooms) та простори імен (namespaces) для логічного групування з'єднань;
- Вбудована підтримка бінарних даних.

**Концепції Socket.io:**

- **Events (події):** іменовані повідомлення, які передаються між клієнтом та сервером;
- **Rooms (кімнати):** довільні канали, до яких можна приєднувати sockets для групової комунікації;
- **Namespaces (простори імен):** окремі точки підключення для логічного розділення функціональності;
- **Acknowledgements (підтвердження):** функції зворотного виклику для підтвердження отримання повідомлень.

### Оптимізація роботи з базою даних

**Індексування** є критично важливим для продуктивності бази даних. Індекси прискорюють операції читання, створюючи додаткову структуру даних, яка дозволяє швидко знаходити записи. Ціна цього — повільніші операції запису й додаткове місце на диску, тому індексувати потрібно лише колонки, які справді використовуються у пошуку, з'єднаннях і сортуванні.

**Типи індексів у PostgreSQL:**

- **B-tree індекси:** стандартні індекси, ефективні для операцій порівняння та сортування;
- **Hash індекси:** оптимізовані для простих операцій рівності;
- **GiST та GIN індекси:** для повнотекстового пошуку та складних типів даних;
- **Складені (composite) індекси:** індекси по кількох колонках для складних запитів; порядок колонок має значення.

**N+1 проблема** виникає коли додаток виконує один запит для отримання списку записів, а потім N додаткових запитів для отримання пов'язаних даних для кожного запису. Це призводить до значного уповільнення роботи.

**Рішення N+1 проблеми:**

- **Eager Loading:** завантаження пов'язаних даних разом з основним запитом;
- **Шаблон DataLoader:** групування (batching) та кешування запитів;
- **З'єднання (JOIN):** об'єднання таблиць на рівні бази даних. У Prisma за замовчуванням `include` виконує окремі запити для кожної зв'язаної таблиці (їх кількість не залежить від кількості записів), а стратегію `join` можна ввімкнути параметром `relationLoadStrategy`.

**Кешування** зменшує навантаження на базу даних, зберігаючи часто використовувані дані в пам'яті. Redis є популярним сховищем даних в оперативній пам'яті для кешування у вебзастосунках. Кеш потрібно інвалідувати (очищати) при зміні даних, інакше користувачі бачитимуть застарілі значення.

### Розгортання та хостинг

**Platform as a Service (PaaS)** — це рішення, що надають готову інфраструктуру для розгортання застосунків. Для Node.js популярні Render, Railway, Fly.io та інші. Умови безкоштовних тарифів змінюються часто, тому перед вибором перевіряйте актуальну документацію. Для цієї лабораторної роботи важливо знати такі особливості безкоштовного рівня Render (станом на вересень 2026 року):

- безкоштовний вебсервіс «засинає» після 15 хвилин без запитів, а перший запит після цього триває до хвилини (холодний старт). З'єднання WebSocket при цьому розриваються, клієнти мають перепідключатися;
- файлова система вебсервісу тимчасова: завантажені файли (наприклад, через Multer) зникають після кожного перезапуску чи повторного розгортання. Для постійного зберігання потрібне зовнішнє сховище файлів (S3-сумісне) або платний постійний диск;
- безкоштовна база PostgreSQL діє лише 30 днів, після чого є 14 днів пільгового періоду, а далі її разом з даними видаляють. Якщо потрібна база на весь семестр, скористайтеся окремим постачальником баз даних із безкоштовним рівнем без обмеження терміну;
- Heroku та Fly.io повноцінного безкоштовного рівня не мають.

**Основні кроки розгортання:**

1. Підготовка застосунку до роботи в робочому середовищі (production);
2. Налаштування змінних середовища на хостингу;
3. Підключення до бази даних робочого середовища та застосування міграцій командою `prisma migrate deploy` (команду `migrate dev` на сервері не використовують);
4. Налаштування домену та SSL-сертифікатів (більшість PaaS робить це автоматично);
5. Моніторинг та логування застосунку.

### Інтеграція Socket.io

1. Встановити пакети Socket.io для сервера та клієнта (клієнтський пакет потрібен для тестування).

```bash
npm install socket.io
npm install --save-dev socket.io-client
```

2. Інтегрувати Socket.io в застосунок Express.js, створивши окремий файл `src/socket/index.js`. У ньому налаштовано CORS для адреси клієнтської частини, автентифікацію підключень за JWT-токеном та персональну кімнату користувача:

```javascript
import { Server } from 'socket.io';
import { verifyAccessToken } from '../utils/jwt.js';

export function initSocket(httpServer) {
  const io = new Server(httpServer, {
    cors: {
      origin: process.env.FRONTEND_URL || 'http://localhost:5173',
      credentials: true,
    },
  });

  // Автентифікація підключення: клієнт передає JWT у auth.token
  io.use((socket, next) => {
    try {
      socket.user = verifyAccessToken(socket.handshake.auth?.token);
      next();
    } catch {
      next(new Error('unauthorized'));
    }
  });

  io.on('connection', (socket) => {
    // Особиста кімната користувача для персональних сповіщень
    socket.join(`user:${socket.user.userId}`);

    socket.on('room:join', (room, ack) => {
      socket.join(room);
      ack?.({ ok: true });
    });

    socket.on('room:leave', (room) => socket.leave(room));
  });

  return io;
}
```

3. Socket.io підключається не до `app`, а до HTTP-сервера, тому в `src/server.js` потрібно створити його явно. Екземпляр `io` зберігається в застосунку, щоб контролери могли надсилати події:

```javascript
import { createServer } from 'node:http';
import app from './app.js';
import { initSocket } from './socket/index.js';

const PORT = process.env.PORT || 3000;

const httpServer = createServer(app);

// Доступ до io з будь-якого контролера: req.app.get('io').to(room).emit(...)
app.set('io', initSocket(httpServer));

httpServer.listen(PORT, () => {
  console.log(`Сервер запущено на порту ${PORT}`);
  console.log(`Документація API: http://localhost:${PORT}/api-docs`);
});
```

4. Створити базову структуру для обробки подій Socket.io з використанням обробників подій (event handlers).
5. Розширити автентифікацію WebSocket-з'єднань: під час підключення перевіряється токен доступу, а коли він спливає, клієнт має оновити токен (див. лабораторну роботу 2) і перепідключитися з новим значенням `auth.token`.
6. Створити систему кімнат (rooms) для групування користувачів за логікою предметної області.
7. Перевірити роботу автоматичним тестом. Приклад тесту, який перевіряє відхилення підключення без токена, кімнати та персональні сповіщення:

```javascript
import { test, after } from 'node:test';
import assert from 'node:assert/strict';
import { createServer } from 'node:http';
import { once } from 'node:events';
import { io as connect } from 'socket.io-client';
import app from '../src/app.js';
import { initSocket } from '../src/socket/index.js';
import { generateAccessToken } from '../src/utils/jwt.js';

const httpServer = createServer(app);
const io = initSocket(httpServer);
app.set('io', io);
httpServer.listen(0);
await once(httpServer, 'listening');
const url = `http://localhost:${httpServer.address().port}`;
const clients = [];

after(() => {
  clients.forEach((c) => c.close());
  io.close();
});

test('підключення без токена відхиляється', async () => {
  const client = connect(url, { auth: {}, reconnection: false });
  clients.push(client);
  const [error] = await once(client, 'connect_error');
  assert.equal(error.message, 'unauthorized');
});

test('кімнати та персональні сповіщення', async () => {
  const alice = connect(url, { auth: { token: generateAccessToken(1, 'USER') } });
  const bob = connect(url, { auth: { token: generateAccessToken(2, 'USER') } });
  clients.push(alice, bob);
  await Promise.all([once(alice, 'connect'), once(bob, 'connect')]);

  await alice.emitWithAck('room:join', 'project:7');

  // Подія в кімнату отримує лише той, хто до неї приєднався
  const got = once(alice, 'task:updated');
  let bobGot = false;
  bob.on('task:updated', () => (bobGot = true));
  io.to('project:7').emit('task:updated', { id: 5, status: 'done' });
  const [payload] = await got;
  assert.deepEqual(payload, { id: 5, status: 'done' });

  // Персональне сповіщення надходить лише власнику
  const personal = once(bob, 'notification');
  io.to('user:2').emit('notification', { text: 'привіт' });
  assert.deepEqual((await personal)[0], { text: 'привіт' });
  assert.equal(bobGot, false);
});
```

Надсилати події клієнтам з контролерів можна так: `req.app.get('io').to('project:' + projectId).emit('task:updated', task)`.

### Оптимізація бази даних

1. Знайти повільні запити. Увімкніть журнал запитів Prisma (`new PrismaClient({ adapter, log: [{ emit: 'event', level: 'query' }] })` та `prisma.$on('query', e => console.log(e.duration, e.query))`), а потім проаналізуйте найповільніші через `EXPLAIN ANALYZE` у `psql` або pgAdmin (Prisma Studio для цього не призначена).
2. Створити індекси для колонок, які часто використовуються в умовах `WHERE`, `JOIN` та `ORDER BY`. У Prisma індекси описуються в `schema.prisma` атрибутом `@@index` і потрапляють до міграції. Порівняйте результат `EXPLAIN ANALYZE` до і після (`Seq Scan` має змінитися на `Index Scan`).
3. Виявити та усунути проблеми N+1 за допомогою `include` та `select` у запитах Prisma.
4. Впровадити пагінацію для всіх ендпоінтів, які повертають списки даних.
5. Додати кешування для даних, які рідко змінюються, використовуючи кеш у пам'яті процесу або Redis, та продумати його інвалідацію.

## ❓ Контрольні запитання

1. Чим WebSocket відрізняється від HTTP та від періодичного опитування (polling)? Коли WebSocket виправданий, а коли достатньо звичайних HTTP-запитів?
2. Що додає Socket.io порівняно з «чистим» WebSocket? Чому клієнт Socket.io не може підключитися до звичайного WebSocket-сервера?
3. Чим відрізняються кімнати (rooms) від просторів імен (namespaces)? Як ви використали кімнати у своєму проєкті?
4. Як у вашому застосунку автентифікуються WebSocket-з'єднання? Що відбувається, коли токен доступу спливає під час активного з'єднання?
5. Як клієнт відновлює стан після втрати з'єднання та повторного підключення? Які події можуть бути пропущені?
6. Як працює B-tree індекс? За якими критеріями ви обирали колонки для індексування і яка ціна індексів?
7. Що таке проблема N+1? Як ви її виявили та усунули за допомогою Prisma?
8. Що показує `EXPLAIN ANALYZE`? Чим `Seq Scan` відрізняється від `Index Scan`?
9. Навіщо потрібен Redis-адаптер під час горизонтального масштабування Socket.io? Чому за кількох екземплярів сервера потрібні «липкі» сесії (sticky sessions)?
10. Які обмеження безкоштовного тарифу вашого хостингу ви врахували (засинання, тимчасова файлова система, термін дії бази даних)? Чим `prisma migrate deploy` відрізняється від `prisma migrate dev`?
