# Лабораторна робота 3. Real-time функціональність та фіналізація backend

## 🎯 Мета роботи

Здобути практичні навички впровадження real-time комунікації у вебдодатки з використанням WebSocket технології, навчитися оптимізувати роботу з базою даних, проводити комплексне тестування серверних застосунків та розгортати їх на production хостингу.

### Вибір функціональності для real-time оновлень

Залежно від  предметної області, потрібно визначити, які саме функції потребують real-time оновлення. Наприклад:

- **Система управління завданнями:** миттєве оновлення статусу завдань, сповіщення про нові коментарі, онлайн-статус користувачів;
- **Інтернет-магазин:** сповіщення про зміну статусу замовлення, онлайн-чат з підтримкою, оновлення кількості товару на складі;
- **Блог-платформа:** миттєве відображення нових коментарів, лайків, сповіщення про нові публікації від авторів;
- **Система бронювання:** real-time оновлення доступності ресурсів, сповіщення про підтвердження бронювання;
- **Освітня платформа:** миттєві сповіщення про нові завдання, онлайн-статус викладачів, live оновлення прогресу;
- **Соціальна мережа:** миттєві повідомлення, сповіщення про нові пости, онлайн-статус друзів;
- **Система управління подіями:** real-time оновлення реєстрацій, сповіщення про зміни в розкладі.

## 📚 Теоретичні відомості

### WebSocket протокол

**WebSocket** є комунікаційним протоколом, який забезпечує full-duplex (двосторонній) канал зв'язку через одне TCP з'єднання. На відміну від HTTP, де клієнт завжди ініціює запит, WebSocket дозволяє серверу надсилати дані клієнту в будь-який момент без попереднього запиту.

**Основні переваги WebSocket:**

- Низька латентність комунікації між клієнтом та сервером;
- Зменшене навантаження на мережу порівняно з polling методами;
- Підтримка двостороннього обміну даними в реальному часі;
- Ефективне використання ресурсів сервера.

**Процес встановлення WebSocket з'єднання:**

1. Клієнт надсилає HTTP запит з заголовком `Upgrade: websocket`;
2. Сервер підтверджує upgrade та повертає статус 101 Switching Protocols;
3. З'єднання переходить від HTTP до WebSocket протоколу;
4. Встановлюється persistent з'єднання для двостороннього обміну повідомленнями.

### Socket.io бібліотека

**Socket.io** є JavaScript бібліотекою для real-time, двосторонньої комунікації між веббраузерами та серверами. Вона надбудовується над WebSocket протоколом, додаючи додаткові можливості.

**Ключові особливості Socket.io:**

- Автоматичний fallback до HTTP long-polling якщо WebSocket недоступний;
- Автоматичне reconnection при втраті з'єднання;
- Підтримка broadcasting повідомлень множині клієнтів;
- Система rooms та namespaces для логічного групування з'єднань;
- Вбудована підтримка бінарних даних.

**Концепції Socket.io:**

- **Events (події):** іменовані повідомлення, які передаються між клієнтом та сервером;
- **Rooms (кімнати):** довільні канали, до яких можна приєднувати sockets для групової комунікації;
- **Namespaces (простори імен):** окремі endpoints для логічного розділення функціональності;
- **Acknowledgements:** callback функції для підтвердження отримання повідомлень.

### Оптимізація роботи з базою даних

**Індексування** є критично важливим для продуктивності бази даних. Індекси прискорюють операції читання, створюючи додаткову структуру даних, яка дозволяє швидко знаходити записи.

**Типи індексів у PostgreSQL:**

- **B-tree індекси:** стандартні індекси, ефективні для операцій порівняння та сортування;
- **Hash індекси:** оптимізовані для простих операцій рівності;
- **GiST та GIN індекси:** для повнотекстового пошуку та складних типів даних;
- **Composite індекси:** індекси по множині колонок для складних запитів.

**N+1 проблема** виникає коли додаток виконує один запит для отримання списку записів, а потім N додаткових запитів для отримання пов'язаних даних для кожного запису. Це призводить до значного уповільнення роботи.

**Рішення N+1 проблеми:**

- **Eager Loading:** завантаження пов'язаних даних разом з основним запитом;
- **DataLoader pattern:** батчинг та кешування запитів;
- **Join операції:** об'єднання таблиць на рівні бази даних.

**Кешування** зменшує навантаження на базу даних, зберігаючи часто використовувані дані в пам'яті. Redis є популярним in-memory сховищем для кешування в вебдодатках.

### Деплой та хостинг

**Platform as a Service (PaaS)** рішення надають готову інфраструктуру для розгортання застосунків. Популярні PaaS для Node.js додатків включають Render, Railway, Fly.io та Heroku.

**Основні кроки деплою:**

1. Підготовка додатку до production середовища;
2. Налаштування змінних середовища на хостингу;
3. Підключення до production бази даних;
4. Налаштування domain та SSL сертифікатів;
5. Моніторинг та логування застосунку.
